# Communications Search, Export & Retention — FE guide

Align the ProductSuite FE with these BE contracts. Mirror Lovable UX (`account-payflow-ai` → `communication-table.tsx`, `communication-export.tsx`, Payment Options retention), but call **real APIs** below — do not keep mock data.

Also see `MESSAGE_VERSIONS_FE.md` for the separate communication-variants story.

---

## 1. List / search communications

`GET /payflow/comms`

### Query params

| Param | Notes |
|---|---|
| `client_id` | Master client |
| `portfolio_id` | Sub-client / portfolio (must belong to selected client) |
| `recipient_email` | Substring match on recipient |
| `date_from`, `date_to` | ISO datetime — filters on **sent** timestamp (`sent_at`, fallback `created_at`) |
| `status` | Existing status enum |
| `channel` | `Email` / `SMS` |
| `purpose`, `workflow` | Existing |
| `search` | Unified text: customer, email, account ref, client name, subject, code, … |
| `limit`, `offset` | Pagination (max 500) |

### Behaviour

- Filters combine (AND).
- Response includes `total` for “N communications match…”.
- **Retention:** rows older than the client’s `communication_retention_days` (from `sent_at`) are **excluded**. They remain in the DB but must not appear in list, detail, or export.

### FE helpers already added

```ts
listPayflowComms({ client_id, portfolio_id, recipient_email, date_from, date_to, search, … })
```

### UI (Lovable parity)

- Unified search placeholder: “Search client, customer, email or account”.
- Inline **From / To** dates with **Apply** (only when dirty) and persistent **Reset**.
- Other filters (client, portfolio, channel, status, …) can apply immediately.
- Client Communications tab: pre-scope `client_id`, hide client filter (`showClientFilter={false}` pattern).
- Show match count + empty state mentioning retention.

## 2. Generate Exportable View

`POST /payflow/comms/export?…same filters…&format=json|html`

Uses the **same filters as the list**. Returns **all** matching retained emails (not just the current page). Ordered oldest → newest.

### `format=json` (preview)

```json
{
  "title": "Email Communication History",
  "client_name": "Masterpens",
  "portfolio_name": "Joavan",
  "recipient_email": null,
  "date_from": "…",
  "date_to": "…",
  "total_emails": 12,
  "generated_at": "…",
  "emails": [
    {
      "id": 1,
      "sent_at": "…",
      "from_email": "collections@…",
      "to_email": "customer@…",
      "subject": "…",
      "status": "Delivered",
      "body": "full retained text",
      "body_lines": ["…"],
      "account_reference": "…",
      "customer_name": "…"
    }
  ]
}
```

### `format=html` (download / print → PDF)

- Returns `text/html` attachment `email-communication-history.html`.
- FE: open blob in a new window and `print()`, or trigger download — same pattern as Lovable’s “Download PDF”.
- Content is the **retained** subject/body as stored — never re-generated by AI.

### FE helpers

```ts
exportPayflowComms({ …filters })           // JSON preview
downloadPayflowCommsExportHtml({ …filters }) // HTML blob for PDF print
```

### UI

1. Button **Generate Exportable View** (enabled when filters applied; disabled when `total === 0`).
2. Dialog preview: header block + one section per email.
3. **Download PDF** → HTML print dialog (or save HTML).
4. Scope follows current filters (global Communications or client tab).

## 3. Client retention setting

### Read

Client detail includes:

```json
"communication_retention_days": 30
```

Default **30**. Presets: **30 / 60 / 90 / 180** + **Custom** (any integer ≥ 1).

### Update

`POST /payflow/clients/{id}/update`

```json
{
  "communication_retention_days": 90,
  "confirm_retention_shorten": true
}
```

| Rule | Behaviour |
|---|---|
| Lengthen (30 → 90) | Allowed without confirmation |
| Shorten (90 → 30) | Requires `confirm_retention_shorten: true` or BE returns 400 |
| Location | Client Configuration → **Payment Options** section (Lovable) |

### FE payload

```ts
updatePayflowClient(id, {
  communication_retention_days: 90,
  confirm_retention_shorten: true, // only when newDays < oldDays
})
```

Copy: “Determines how long this Client’s communication history and content remain available for search and export…”

Show: “Currently retained: **N days** of communication history.”

## 4. Permissions

- Search / export / detail: `view_communications` for that client.
- Change retention: same client edit permission as Payment Options (`edit_client` / section save rules).
- Users never see other clients’ communications.

---

## 5. Acceptance checklist (FE)

- [ ] Filters: client, portfolio, recipient email, date range, status, channel (+ unified search)
- [ ] Apply / Reset for date range; portfolio options follow selected client
- [ ] Listing shows sent time, recipient, client, portfolio, subject, status, view details
- [ ] Match count + empty/loading/error states
- [ ] Generate Exportable View → preview → download/print PDF of **all** matching retained emails
- [ ] Retention field on Client → Payment Options (30/60/90/180/Custom)
- [ ] Shortening retention asks for confirmation
- [ ] Expired records never appear in list, detail, or export
- [ ] Existing list/detail/tracking still works

---

## 6. Out of scope for FE

- AI summaries of history
- Restoring purged/hidden records
- Per–sub-client retention
- Editing previously sent content
